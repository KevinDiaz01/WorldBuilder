# WorldBuilder UX session — October 16, 2026 (v0.3.179)

Source: user-supplied **14:27** narrated screen recording on Windows, along with preceding chat clarifications. This is an issue/requirements document, **not a claim that requested behavior is implemented**. The spoken-audio automated transcript was unreliable in spots: treat the specific verbal interpretations below as review notes, not verbatim quotations. The visual interactions and current source code were separately inspected.

## Product direction (critical)

WorldBuilder should be a game-like editor for building VRChat worlds with **real, discoverable, downloadable assets**. Do not respond to requests for trees/water/terrain/materials by inventing more procedural placeholder objects. Retain primitive geometry as useful starter or backdrop tools, but prioritize a seamless **Find → Download → Organize → Use** workflow.

The site browser has three source tabs: **Poly Haven, Sketchfab and ambientCG**. The first selected source and its initial page must reflect **the current asset type**. For example, a tree search must not start at generic models; a material search should start at ambientCG; skyboxes/HDRIs should open an actual HDRI library, not 3D models. Sites unable to provide a given type should say so rather than silently showing unrelated materials or generic models. Tabs, back/forward and Close must remain visible; do not restore the buggy Win32 SetParent child-window embedding from pre-#179.

A visual **My Assets** library should show **all** successfully downloaded/imported assets once, with category grouping and search. Selecting Furniture, Kitchen, Bathroom, Plants, Outdoor, Materials, etc. should filter already-owned items and offer a **Find More [category]** action, including when empty. The source category should be remembered at download/import time; don't rely entirely on filename guessing. Allow user to correct the category. Materials, placeable models and HDRIs must have different apply workflows.

## Timeline observations / questions

- **00:00–01:00 (Build):** Multiple overlapping navigation concepts: left tool rail, bottom Build Collection, Studio dialog and a separate right-side panel. Prioritize a clear, uncluttered viewport with only context-relevant controls. Review which Build commands truly need duplicating.
- **01:00–03:30 (Decorate):** Library contains a few imported entries, and many categories have empty states. The left rail has Sofa/Table and other template object tools that compete with downloadable furniture categories. Treat furniture/lighting/decor as asset categories; leave geometry tools or primitives separately named.
- **03:30–06:30 (Catalog navigation):** Switching tabs should show the relevant owned models and contextual sourcing action. My Assets is the complete organized collection, not a generic default that makes every other tab redundant. Material swatches are quick starters, not the finished material system.

Main path should lead to actual terrain/plant/water assets and appropriate editing tools; existing primitive placeholders may remain optional for early blocking or backgrounds. A terrain-brush/surface editing workflow is separate from placing trees.
- **09:00–10:00 (Asset browser):** Browser window/source switching is demonstrated. #179 restored a visible titlebar and tabs. Keep category-specific searches consistent across all tabs and ensure reopening for a new category works.
- **10:00–11:00 (Catalog presentation):** Bottom scroll strip is oversized/high contrast and draws attention away from the world. Improve slim scrollbar behavior and catalog legibility rather than making the catalog occupy more of the screen.
- **11:00–13:00 (Outdoor tools and object controls):** Object selection shows a small overlay of directional move buttons and a right inspector at the same time. Replace with clearer direct manipulation and contextual inspector rather than two unrelated control systems. Terrain should eventually be edited as terrain, not merely moved as a giant box.
- **13:00–14:27 (Environment):** Add a discoverable **Skybox/HDRI** category with relevant browsing and *actual* import/apply to the editor environment; current Day/Sunset/Night/Overcast gradient colors are not a replacement for imported sky assets. Verify what export to VRChat can preserve.

## Immediate implementation priorities

1. **Asset-hub navigation contract:** One consistent reusable category model, correct selected category, contextual Find More/Import actions for empty and populated tabs, My Assets organizational filters, no duplicate misleading sample-object entries.
2. **Provider-category matrix:** Explicit asset kinds (3D Model, PBR Material/Texture, HDRI/Skybox) and per-provider category URLs / support. Choose best provider first without hiding other applicable tabs. Audit actual provider URLs against live pages.
3. **Download-to-library flow:** Preserve provider + requested category metadata alongside every download. Automatic import/validation. Show downloading, imported, unsupported-format or failed statuses. Allow recategorizing individual assets.
4. **Apply flows:** Place 3D models with size/ground alignment; apply PBR albedo/normal/roughness to selected surfaces; import and select supported equirectangular HDRI/skybox without losing backup project data. Distinguish lighting emitters from decorative lighting meshes.
5. **UX cleanup:** Collapsible bottom asset tray, subtle scrolling, no redundant left rail icons, one inspector, visible close/escape behavior, context-relevant tools.
6. **Later: advanced terrain and realism:** Sculptable heightfield, vegetation paint, realistic water surfaces and sky environment. Do not replace the asset hub with procedural-only improvements.

## Current code audit (at v0.3.179)

- `asset-browser/Program.cs`: browser routes Trees to Poly Haven category and Materials to ambientCG, but sets the ambientCG provider URL to `type=Material` **for every category**. Skybox/HDRI is not a supported category. Browser uses a separate titled window to avoid toolbar clipping.
- `WorldBuilderRuntime.cs`: category index zero is My Assets/All; the category picker and "Find" route have logic in several places rather than one source of truth. Bottom collection and left rail show overlapping commands. Built-in Couch/Table remain generic object tools.
- `AssetHub.cs`: imported model category is largely guessed from the filename. The requested browsing category is not reliably persisted into import metadata. `MaterialLibrary` detects texture-only downloads separately.
- The #174 shader regression is repaired; #179 build passed. **None of this proves the complete editor can publish exported assets to VRChat.**

## Acceptance tests before publishing changes

- Switching Build/Decorate/Landscape does not unexpectedly change an object or open an irrelevant tool.
- My Assets lists everything once with sorting/filtering; Kitchen, Trees, Materials and Skyboxes each open correct source types.
- Browser toolbar remains visible and closable on Windows 100%/150% DPI, including every provider switch.
- Download a real model and material; they appear under expected categories with true thumbnails; apply/place and save/reopen.
- Download/select an HDRI; editor environment changes predictably and persists in save; document VRChat export behavior and limitations.
- Existing worlds and project backups are unchanged across upgrades; rollback works.
- CI compiles; do **manual** Windows visual checks at 1600x900 and laptop resolution.

## Guardrails

- No invented upgrade success messages; only CI status establishes compilation, not desktop behavior.
- Avoid releasing a dozen loosely related tiny builds. Make focused changes, test them, then publish a coherent release.
- Don't improve placeholder trees, water or terrain as a substitute for the user's requested asset discovery system.
